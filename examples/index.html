alpinejs-component@3

x-component

Render a template from the page or a URL into any element, fill its slots, and keep the result in the light DOM, where the rest of your page can reach it.

  • Page templates
  • Remote templates
  • Default and named slots
  • Lifecycle events

Coming from v2

v3 renders into the light DOM instead of a shadow root, so delete x-component-styles. Your stylesheet reaches component content on its own now, and nothing else in the directive changed.

Every form below shows the template it renders, the markup that uses it, and the live result, so you can read a behaviour and copy it in one pass.

template/page

Render a template from the page

The expression is the id of a <template> on the page. Its content is cloned into the host element and initialized against the host's scope, so item below resolves to the host's data, including inside an x-for.

styles/scope

Style a component with the page's stylesheet

Nothing opts in. The cards above wear this page's Tailwind utilities and its .card class, compiled by the browser build that reads the markup inside every <template>. In v2 the shadow boundary hid rendered content from that scan and from the stylesheet, which is why the old version of this page had to safelist utilities by hand. Bare element selectors still need scoping, and @scope does that job now that x-component-styles is gone.

slots/named

Fill a component's slots

A <template x-slot> on the host fills the default <slot>, and x-slot="actions" fills the one named actions. A slot nobody fills keeps its own children as fallback. Slot content is authored on the host, so it reads and writes the host's scope: the heading below comes from the component's own data, while everything inside the slots is the host's Katherine Johnson, and the buttons update the host.

slots/loops

Repeat a slot for every row

A <slot> nested in an x-for or x-if template is filled once per iteration, and it is the one place slot content does not get the host's scope. The badges below ask for label, which is host scope on the host, and render the component's value instead. Alpine clones those templates, and the binding that ties projected content to the host does not survive the clone. Keep slots out of x-for and x-if when the content needs host scope.

component/dynamic

Swap the component at runtime

The expression is reactive. Change it and the tree that was mounted is destroyed and the new one rendered in its place, against the same host data. An expression that resolves to an empty string unmounts and leaves the host empty.

template/url

Load a template from a URL

With the .url modifier the expression is a URL to fetch rather than the id of a template on the page. Everything else is the same, slots included. Because the fetch is asynchronous, the host emits x-component:loading and then x-component:loaded; the events bubble, so the log below listens on the wrapper rather than the host. A same-origin URL is required unless you add .external, and responses are cached by URL.

boundary/light-dom

Reach across the component boundary

The label outside the component focuses the input inside it, that input submits with the form wrapped around the component, and $refs and $root resolve past the host into the surrounding tree. document.querySelector finds the input too. Every one of these was broken by the shadow boundary in v2, and together they are the reason v3 renders into the light DOM.

errors/failure

Handle a template that will not load

Each of these leaves the host empty and emits x-component:error with the source and the error, so expect console noise from this section. A URL that fails is not cached, so retrying the same host with a working URL succeeds.
